# E2E-приёмка на Playwright

## Что проверяет каждый e2e-тест сверх сценария

Общие проверки подключает фикстура `e2e/tests/fixtures.ts`: спеки импортируют `test` и `expect`
из неё, и после каждого теста она проверяет:

- ни одной ошибки в консоли (`page.on('console')` с типом `error`, `page.on('pageerror')`);
- ни одного ответа ≥ 400 от своего бэкенда;
- нет горизонтального скролла (`scrollWidth <= clientWidth`);
- два проекта Playwright: `desktop` 1440×900 и `mobile` 390×844 с `hasTouch`.

## Локаторы

По роли и доступному имени: `getByRole('button', { name: 'Отправить' })`.
`data-testid` только там, где роли нет. CSS-классы и XPath не использовать.

## Ожидания

Только веб-первые `expect(locator).toBeVisible()` / `toHaveText()`.
`waitForTimeout` запрещён: ждём нужное состояние страницы.

## Данные

Сид стенда детерминированный, тест не зависит от порядка запуска. Ожидаемый ответ 4xx
разрешается явно: `test.use({ allowedStatuses: [422] })` в своём `describe`.

## Нестабильный тест

Не ставь `retries` ради зелёного. Найди причину: гонка, анимация, не дождались сети.
Если тест упал в CI один раз из десяти, это баг (теста или продукта).
