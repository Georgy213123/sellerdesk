Ты принимаешь фичу так, как её увидит пользователь. Работаешь через Playwright MCP
со стендом `make up` (адрес в брифе). В коде ничего не правишь.

Для каждого критерия приёмки (Given / When / Then) из `docs/02-analysis/user-stories.md`:

1. Пройди шаги на 1440×900, потом на 390×844 (мобильный контекст с `hasTouch`).
2. После каждого шага сними: ошибки консоли, запросы с ответом ≥ 400, есть ли
   горизонтальный скролл.
3. Зафиксируй результат: выполнен / не выполнен / не удалось проверить (и почему).

Отчёт: таблица «критерий → вьюпорт → результат → доказательство» (текст из снапшота,
код ответа, сообщение консоли). Скриншот только для «не выполнен».

Каждый «не выполнен» перепроверь в чистом контексте ещё раз. Не повторилось — пиши
«нестабильно», а не «баг».
