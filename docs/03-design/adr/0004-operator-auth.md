# ADR-0004. Вход оператора по JWT в демо

- Статус: принято
- Дата: 2026-10-25

## Контекст и проблема

Рабочее место отвечает покупателям от имени продавца, держать его открытым без входа нельзя
даже в демо: это видно по контракту, и e2e должен проходить вход. Полноценные роли и журнал
действий в демо не входят.

## Варианты

1. Без входа, с пометкой в README.
2. Одна учётка из сида, пароль из окружения, JWT в заголовке `Authorization`.
3. Внешний провайдер (OIDC).

## Решение

Вариант 2. Пароль хранится как PBKDF2-SHA256 (стандартная библиотека), токен — HS256 с секретом
из `JWT_SECRET`, срок 8 часов. Фронт хранит токен в `sessionStorage`. Значения по умолчанию —
только для демо, в `.env.example`.

## Последствия

- Плюс: все рабочие ручки закрыты, контракт честно показывает `HTTPBearer`.
- Минус: нет ролей, отзыва токенов и журнала. Это модуль «Роли и журнал действий» (⬜).
- Переход на OIDC меняет только `app/security.py` и зависимость `current_operator`.
