# ADR-0004. Автономный агент-маркетолог: обвязка долгого прогона
Статус: принято 2026-11-04.

**Контекст.** Раз в неделю нужно разобрать отзывы, вопросы и чаты, найти повторяющиеся претензии и
предложить шаблон ответа или правку карточки. Прогон идёт без человека минуты и может упасть
посередине. Агент не должен ничего публиковать и писать покупателям.

**Решение.**
- Прогон — строка `agent_runs`: стадия и курсор в чекпоинте (JSONB), бюджет токенов, лимит шагов.
  Шаг (результат, чекпоинт, расход, журнал) фиксируется одной транзакцией. Упавший прогон
  продолжается с первого несохранённого шага: пачки не классифицируются повторно, предложения
  не дублируются (`UNIQUE (run_id, theme_key, kind)`).
- Аренда с heartbeat, как у `sync_jobs`: прогон с истёкшей арендой подбирает следующий запуск.
  Запись шага защищена значением heartbeat, поэтому медленный процесс не затрёт результат того,
  кто подобрал прогон.
- Один активный прогон на вид: частичный уникальный индекс.
- Бюджет проверяется перед шагом, исчерпание — статус `budget_exhausted`, сделанное остаётся.
  Перед вызовом LLM в чекпоинт коммитится резерв: потолок ответа плюс консервативная оценка входа.
  Ответ заменяет резерв фактическим расходом; если процесс умер между вызовом и записью, следующий
  запуск списывает резерв. Превышение бюджета ограничено одним резервом.
- Временная ошибка провайдера не убивает прогон: пишется `error`, аренда отдаётся, растёт счётчик
  попыток в чекпоинте, следующий запуск (таймер, CLI, `POST /api/agent/runs`) продолжает тот же
  прогон. После `AGENT_MAX_ATTEMPTS` подряд (3) прогон `failed`; неожиданное исключение — сразу.
- Фоновая задача API привязана к `run_id` и только захватывает свой прогон.
- В модель уходит только текст, прошедший `mask_pii`; имена покупателей не читаются вовсе.
- Решает человек: одобренный «шаблон» создаёт шаблон ответа, «правка карточки» лишь помечается
  одобренной. Адаптера записи в площадку нет, это отдельное решение.

**Не сделано.** Heartbeat между шагами, а не отдельным потоком: шаг с повторами LLM должен
укладываться в `AGENT_LEASE_S`. Распараллеливания пачек нет.
