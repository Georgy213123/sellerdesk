# ADR-0001. Стек: FastAPI + PostgreSQL + React

- Статус: принято
- Дата: 2026-10-20

## Контекст и проблема

Нужен MVP рабочего места оператора: REST API, хранилище с надёжными уникальными ограничениями
(на них держится идемпотентность синхронизации и ответов), веб-интерфейс, который работает и на
телефоне. Код в основном пишут агенты, поэтому стек должен быть типизированным и проверяемым
линтерами.

## Варианты

1. FastAPI + SQLAlchemy 2 + PostgreSQL, фронт на React + TypeScript.
2. Django + Django REST Framework + PostgreSQL, шаблоны или React.
3. Node.js (NestJS) + Prisma + PostgreSQL, фронт на React.

## Решение

Вариант 1.

- OpenAPI генерируется из кода, контракт выгружается в `openapi.yaml` и сверяется тестом.
- pydantic v2 и mypy strict ловят большую часть ошибок сгенерированного кода до запуска.
- PostgreSQL даёт `INSERT ... ON CONFLICT` и `timestamptz` — оба нужны прямо в логике
  (ADR-0002, ADR-0003, BUG-02).
- React 19 + Vite: быстрый цикл, Vitest и Testing Library для unit-тестов компонентов.

## Последствия

- Плюс: один язык типов на бэкенде (pydantic), строгий TypeScript на фронте.
- Минус: админку как в Django придётся писать самим, если она понадобится.
- Минус: синхронные сессии SQLAlchemy; для демо этого хватает, при росте нагрузки синхронизацию
  нужно вынести в отдельный воркер (см. ADR-0002).
