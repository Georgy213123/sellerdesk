Второй круг ревью Codex (gpt-6.1-sol) — только исправление CR-06/07. Четыре находки, все
подтверждены тестами.

### Исправлено
- R2-01: `POST /api/sync` больше не падает `NoResultFound`, если активная задача завершилась между конфликтом вставки и выборкой.
- R2-02: миграция 0002 закрывает уже существующие дубли активных задач перед созданием уникального индекса.
- R2-03: запоздавший обработчик задачи, закрытой как зависшая, её не оживляет: захват `queued → running` и запись итога — условные UPDATE.
- R2-04: тест гонки CR-06 детерминирован — синхронизация по ожиданию блокировки в `pg_stat_activity`, без таймаутов.

## [0.3.1] — 2026-11-03

Исправления по независимому ревью Codex (gpt-6.1-sol): 13 находок, все подтверждены тестами,
CR-01 — только для чатов. Таблица — в [04-ai-development.md](04-ai-development.md).

### Исправлено
- BUG-06 (CR-01): ключ идемпотентности передаётся площадке; потерянное подтверждение больше не даёт второй ответ.
- BUG-07 (CR-02): поздний AI-черновик или ответ шаблоном не попадает в другой открытый чат.
- BUG-08 (CR-03): внешние id заглушки площадки — UUID; после перезапуска API ответ не падает на уникальном индексе.
- CR-04: повтор ответа шаблоном после сетевой ошибки идёт с тем же ключом.
- BUG-09 (CR-05): ключ ответа привязан к тексту; тот же ключ с другим текстом — 409.
- BUG-10 (CR-06): одна активная задача синхронизации держится частичным уникальным индексом (миграция 0002).
- CR-07: зависшая задача синхронизации старше `SYNC_JOB_STALE_AFTER_S` (600 с) помечается `failed`.
- CR-08: при загрузке страницы во время синхронизации кнопка «Обновить» продолжает опрос.
- CR-09: открытая карточка чата перечитывается после синхронизации.
- CR-10: «Показать ещё» в ленте и отзывах вместо обрезки первыми 100 записями.
- CR-13: тест двойной отправки проверяет синхронную защиту, а не `disabled`.

### Изменено
- CR-11: `POST /api/templates` с неизвестной переменной отвечает 400 (было 422 с телом, не совпадавшим с контрактом).
- CR-12: в контракте `POST /api/sync` описан ответ 200 при уже активной задаче.
- `MarketplaceClient.send_chat_message` принимает `idempotency_key`.

## [0.3.0] — 2026-11-03

### Добавлено
- Шаблоны автоответов с переменными `{{buyer_name}}`, `{{product}}`, `{{order_number}}`,
  `{{marketplace}}`, `{{operator_name}}` и правилом «не подставилось — черновик с причиной».
- Справочник шаблонов: список и создание, неизвестные переменные отклоняются.
- Заголовок `Idempotency-Key` для ответов в чат.
- Мобильная вёрстка: на телефоне карточка чата открывается вместо ленты.
- e2e на Playwright, вьюпорты 1440×900 и 390×844.
- Тест сверки `openapi.yaml` с кодом, тест сверки миграций с моделями.

### Исправлено
- BUG-01: двойной клик «Отправить» отправлял два ответа.
- BUG-02: лента сортировалась по местному времени площадок вместо UTC.
- BUG-03: повторная синхронизация дублировала сообщения.
- BUG-04: HTML из текста отзыва исполнялся в карточке.
- BUG-05: переменная шаблона в другом регистре уходила покупателю буквально.

## [0.2.0] — 2026-10-27

### Добавлено
- Отзывы и вопросы: список, фильтры по типу, оценке и наличию ответа, ответ.
- AI-черновик ответа через интерфейс `LLMProvider`, заглушка по умолчанию.
- Фоновая синхронизация по кнопке «Обновить» (`POST /api/sync`, 202).
- Вход оператора по JWT.

## [0.1.0] — 2026-10-22

### Добавлено
- Интерфейс `MarketplaceClient` и заглушка `MockMarketplace` для трёх площадок.
- Синхронизация чатов в PostgreSQL с upsert по внешнему id.
- Единая лента чатов с фильтром по площадке и статусу, карточка чата, ответ.
